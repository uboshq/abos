## ✗ ব্লকার — টাকা আদায় করাই যায় না নতুন কোম্পানিতে

| | |
|---|---|
| **পর্দা** | বিক্রয় › আদায় (`/sales/collections/create`) |
| **যা করতে চেয়েছি** | বিক্রি করা বিলের ২০০ টাকা আদায় করা |
| **যা হয়** | "যেখানে টাকা ঢুকল" ড্রপডাউনে **তিনটাই বিকল্প, তিনটাই অচল** |

তিনটাই চেষ্টা করে দেখা হয়েছে, তিনটাই প্রত্যাখ্যাত:

```

ব্যাংক (61)                → "ব্যাংক" একটা মাথা, খাত নয়…
মোবাইল ব্যাংকিং MFS (286)  → "মোবাইল ব্যাংকিং (MFS)" একটা মাথা, খাত নয়…
```

⚠️ **বার্তাটা বলে "নিচের একটা খাত বাছুন" — কিন্তু ড্রপডাউনে নিচে কিছুই নেই।**
তিনটা বিকল্পই মাথা। ব্যবস্থাটা এমন একটা জিনিস বেছে নিতে বলছে যা তালিকায় নেই।

### কারণ (হিসাব তালিকা দেখে)

```
▾ 1101 হাতে নগদ 🔒            ← মাথা, নিচে কোনো সন্তান নেই
▾ 1102 ব্যাংক 🔒              ← মাথা, নিচে কোনো সন্তান নেই
▾ 1105 মোবাইল ব্যাংকিং 🔒     ← মাথা, নিচে কোনো সন্তান নেই
```

নতুন কোম্পানিতে এই তিনটা মাথা বসানো থাকে, **কিন্তু নিচে একটাও পোস্টযোগ্য খাত নেই।**

### প্রমাণ — সমাধানটাও যাচাই করা

ক্যাশ টিল বানালাম (হিসাব › ক্যাশ টিল › নতুন → "প্রধান কাউন্টার")। **সাথে সাথেই**
ড্রপডাউনে নতুন বিকল্প এলো `প্রধান কাউন্টার` (id 307), আর আদায় সফল হলো।

**অর্থাৎ পথটা আছে — কিন্তু কেউ বলে দেয় না।**

⚠️ **ক্রেতার অভিজ্ঞতা:** তিনি মাল বেচতে পারবেন, বিল ছাপাতে পারবেন — **কিন্তু
টাকা আদায় করতে গিয়ে আটকে যাবেন, আর ভাববেন পর্দাটাই ভাঙা।** তাঁর ফোন করার কেউ নেই।

**তিনটার যেকোনো একটা করলেই মেটে:**

1. নতুন কোম্পানিতে একটা ডিফল্ট টিল বসিয়ে দেওয়া
2. ড্রপডাউন থেকে মাথাগুলো বাদ দেওয়া (তালিকা খালি হলে বলা "আগে একটা ক্যাশ টিল বানান")
3. বার্তায় লেখা "ক্যাশ টিল বানান — হিসাব › ক্যাশ টিল" + লিংক

## ⚠ সিস্টেমিক — ভুলের বার্তা ইংরেজিতে, কাঁচা কলামের নাম দিয়ে

গোটা পর্দা বাংলা, লেবেল বাংলা — কিন্তু ভুল করলে বার্তা ইংরেজিতে, আর মাঠের নাম
ডাটাবেসের কলাম:

```
The name en field is required.        ← লেবেল "নাম (ইংরেজি)"

The context field is required.
The qty field must be greater than 0. ← লেবেল "পরিমাণ"
```

**মাপা হয়েছে — মাস্টার ডাটার ৮টা ফর্মেই, আর লেনদেনের ফর্মেও:**

```
units · brands · product-categories · taxes · cost-centers
departments · reason-codes · payment-methods

```

⚠️ ক্রেতা প্রথম দিনেই এটা দেখবেন — নতুন ব্যবসায় প্রথম কাজই মাস্টার ডাটা বসানো,
আর সবাই একবার ঘর খালি রেখে সেভ চাপবেন।

ⓘ **সব বার্তা ইংরেজি নয়** — মজুদের চেয়ে বেশি বিক্রি আর মাথা-বনাম-খাত, দুইটাই
চমৎকার বাংলায় আসে (নিচে দেখুন)। অর্থাৎ **হাতে লেখা বার্তাগুলো বাংলা, আর
ফ্রেমওয়ার্কের নিজের বার্তাগুলো ইংরেজি।** অনুবাদ ফাইলটা বসালেই মেটে।

## ⚠ একই নামে দুইটা পণ্য — তৈরিতে বাধা নেই, বেচার সময় আলাদা করার উপায় নেই

FMART-এ ইচ্ছে করে একই নামে দুইবার পণ্য বানিয়েছি। **দ্বিতীয়বার কোনো সতর্কবার্তা
নেই, কোনো প্রশ্ন নেই — চুপচাপ সেভ।**

```
PRD-0001   কিউএ পরীক্ষা চিনি ১ কেজি   (মজুদ 100)
PRD-0002   কিউএ পরীক্ষা চিনি ১ কেজি   (মজুদ 0)
```

**সরাসরি বিক্রয়ের পণ্য-বাছাইয়ে দুইটা সারি হুবহু একরকম** — শুধু ডানে ১০০ আর ০।
কোড নেই, একক নেই, গুদাম নেই।

ⓘ **এটা আজ সকালের TDEPOT-এর বাগটারই উৎস** — তখন বলেছিলাম "আলাদা করার উপায় নেই",
এখন শূন্য থেকে বানিয়ে **কারণটা প্রমাণ করা গেল**। TDEPOT-এর ডেটার দোষ নয়, নকশার।

**অথচ অন্য সব জায়গায় কোড দেখায়:**

```
পণ্য তালিকা           PRD-0001 · PRD-0002         ✓
খোলা মজুদের ড্রপডাউন   "PRD-0001 - কিউএ পরীক্ষা…"  ✓
ছাপা বিল              "PRD-0001 - কিউএ পরীক্ষা…"  ✓
সরাসরি বিক্রয় বাছাই    শুধু নাম                     ✗
```

**তথ্যটা আছে, কেবল বাছাইয়ের ঘরে দেখানো হয় না।** ওখানে কোডটা বসালেই মেটে।

# ✓ টাকার হিসাব — প্রতিটা ধাপে মিলেছে

শূন্য FMART-এ পুরো চক্র চালানো হয়েছে, আর **প্রতি ধাপে রেওয়ামিল মিলিয়ে দেখা হয়েছে:**

| ধাপ | যা করেছি | রেওয়ামিল |
|---|---|---|
| খোলা মজুদ | ১০০ × ৮০ = **8,000** | মজুদ পণ্য ডেবিট 8,000 · সঞ্চিত মুনাফা ক্রেডিট 8,000 · **মোট 8,000 = 8,000** ✓ |
| বিক্রয় | ৫ × ১০০ = **500** | প্রাপ্য 500 ডে · বিক্রয় 500 ক্রে · COGS 400 ডে · মজুদ 400 ক্রে · **8,900 = 8,900** ✓ |
| আদায় | **200** নগদ | প্রধান কাউন্টার 200 ডে · প্রাপ্য 200 ক্রে · **9,100 = 9,100** ✓ |

**একটা ধাপেও খাতা বেমিল হয়নি।** মুনাফার হিসাবও ঠিক: বিক্রয় ৫০০ − ব্যয় ৪০০ = ১০০।

## ✓ খসড়া → নিশ্চিত — ঠিকভাবে কাজ করে

আদায় সেভ করলে **খসড়া** অবস্থায় থাকে, **খাতায় কিছুই বসে না** (সঠিক)।
"নিশ্চিত করুন" চাপলে তবেই খতিয়ানে যায়। **এটাই হওয়া উচিত।**

## ✓ মজুদের বেশি বিক্রি — আটকায়, আর বাংলায় কারণ বলে

## যে তিনটা ভুল রিপোর্ট এড়ানো হয়েছে

আজ তিনবার প্রায় ভুল জিনিস লিখে ফেলেছিলাম — যাচাই করে বাদ দেওয়া হয়েছে:

**১ · "আদায় নীরবে ব্যর্থ হয়"** — আমার নিজের POST-এ কোনো ভুলবার্তা দেখিনি।
আসলে ব্যবস্থাটা **পরিষ্কার বাংলায় বার্তা দিচ্ছিল**; আমার ছাঁকনি কেবল ইংরেজি
প্যাটার্ন খুঁজছিল বলে ধরা পড়েনি। ফর্ম দিয়ে আবার করে ধরা পড়ল।

**২ · "আদায় খতিয়ানে বসে না"** — সংখ্যা নড়েনি দেখে বাগ মনে হয়েছিল।
আসলে রেকর্ডটা **খসড়া** ছিল, আর খসড়া খাতায় বসে না — **সঠিক আচরণ**।

**৩ · "খাতার যাচাইয়ে গণনার গরমিল"** — স্ক্রিনশটে "৪ টা যাচাই" পড়ে ৮টা কার্ড
গুনেছিলাম। DOM দেখে বোঝা গেল লেখা আছে **"৮ টা"** — আমি বাংলা **৮**-কে **৪**
পড়েছিলাম। **আমার পড়ার ভুল, ব্যবস্থার নয়।**

| সিস্টেমিক | **১** — ভুলের বার্তা ইংরেজিতে, কাঁচা কলামের নামে (১০+ ফর্ম) |
| মাঝারি | **২** — একই নামে পণ্য চুপচাপ · বাংলা নামে কোড ফাঁকা দেখায় |
| টাকার হিসাব | **নির্ভুল** — তিন ধাপে রেওয়ামিল মিলেছে, সংখ্যা তিন জায়গায় এক |

**সবচেয়ে জরুরি কথা:** টাকার অঙ্কে **একটাও ভুল পাইনি** — খোলা মজুদ, বিক্রয়,
COGS, আদায়, সবই নিখুঁত। যে একটা ব্লকার আছে, সেটা হিসাবের ভুল নয়, **পথের বাধা**:
ক্রেতা টাকা আদায়ের পর্দায় পৌঁছে আটকে যাবেন, কারণ ড্রপডাউনে ব্যবহারযোগ্য কিছু নেই।

# দ্বিতীয় পর্ব — ক্রয় চক্র ও ড্রিল-ডাউন (১৪:১৮–১৪:২২)

## ✓ ক্রয় চক্র — হিসাবটা রীতিমতো নিখুঁত

FMART-এ সরবরাহকারী "করিম ট্রেডার্স" বানিয়ে তিনটা ধাপ চালানো হয়েছে:

### ধাপ ১ · সরাসরি ক্রয় বিল (চালান ছাড়া) — ৫০ × ৮০ = ৪,০০০

```
মজুদ           95 → 145                          ✓
1120 মজুদ পণ্য   ডেবিট 12,000 (8,000 + 4,000)     ✓
2110 প্রদেয়      ক্রেডিট 4,000                     ✓
সর্বমোট         13,100 = 13,100                   ✓
```

### ধাপ ২ · মাল বুঝে নেওয়া (GRN) — ২০ × ৮০ = ১,৬০০

```
মজুদ                        145 → 165           ✓
1120 মজুদ পণ্য                ডেবিট 13,600        ✓
2160 প্রাপ্ত মাল, বিল আসেনি     ক্রেডিট 1,600       ✓ ⭐
2110 প্রদেয়                   অপরিবর্তিত 4,000    ✓ (বিল তো আসেনি)
সর্বমোট                      14,700 = 14,700     ✓
```

⭐ **এটা পাকা ERP-র লক্ষণ।** মাল এসেছে কিন্তু বিল আসেনি — এই অবস্থাটার জন্য
আলাদা দায়ের খাত (GRNI accrual)। দায়টা সরবরাহকারীর নামে বসেনি, কারণ এখনো
তাঁর বিলই আসেনি। **ঠিক যেমন হওয়া উচিত।**

### ধাপ ৩ · ওই চালানের বিল — ⚠️ দ্বিগুণ গণনার পরীক্ষা

চালানের পাতায় বোতাম আছে **"এই চালানের বিল করুন"** →
`/purchase/bills/create?purchase_receipt_id=3`, আর ফর্মটা নিজে থেকে ভরে আসে
(`purchase_receipt_line_id` দিয়ে লাইনটা বাঁধা)।

**ফল — দ্বিগুণ গণনা হয়নি:**

```
মজুদ                        165 → 165  (অপরিবর্তিত)  ✓ ⭐
পণ্যের পাতা                  165.00                    ✓
2160 GRNI                   1,600 ডে / 1,600 ক্রে = ০  ✓ পুরো নিষ্পত্তি
2110 প্রদেয়                  4,000 → 5,600 (+1,600)    ✓
"মাল এসেছে, বিল আসেনি" রিপোর্ট  খালি হয়ে গেছে             ✓
সর্বমোট                     16,300 = 16,300           ✓
```

**চালান থেকে বিল করলে মাল দ্বিতীয়বার ঢোকে না, দায় GRNI থেকে সরবরাহকারীর
নামে সরে যায়।** এটাই সঠিক আচরণ, আর ঠিক এটাই হয়েছে।

ⓘ **ক্রস-চেক:** "মাল এসেছে, বিল আসেনি" রিপোর্টের যোগফল (১,৬০০) আর রেওয়ামিলের
2160 খাতের জের (১,৬০০) **হুবহু মিলেছে** — দুইটা আলাদা পথে গোনা একই সংখ্যা।

### ⚠ ছোট একটা অসঙ্গতি — সাহায্যের লেখাটা এক, আচরণ দুই

দুইটা বিল ফর্মেই একই লাইন লেখা:

> "বিল নতুন করে মাল আনে না — দায়টা সরবরাহকারীর নামে সরায়।"

**চালান-বাঁধা বিলে কথাটা সত্যি** (মজুদ বাড়েনি)।
**সরাসরি বিলে কথাটা মিথ্যা** — ধাপ ১-এ ওই বিলই মজুদ ৯৫ থেকে ১৪৫ করেছে।

টাকার ভুল নয়, কিন্তু **উল্টো বোঝায়**: কেউ সরাসরি বিল কেটে ভাববেন মজুদ বাড়েনি,
তারপর আলাদা করে চালানও কাটবেন — তখন সত্যিই দ্বিগুণ হবে।
**লেখাটা চালান-বাঁধা ফর্মেই কেবল দেখানো উচিত।**

## ✓ ড্রিল-ডাউন — প্রতিটা সংখ্যা তার উৎসে নিয়ে যায়

ড্যাশবোর্ডের **২১টা সংখ্যাওয়ালা কার্ডের ২১টাতেই লিংক আছে** — একটাও মরা কার্ড নেই।

**"আজ" টাইলগুলো তারিখ-ছাঁকা তালিকায় নেয়, আর সংখ্যা হুবহু মেলে:**

| কার্ড যা বলে | যেখানে নেয় | সেখানে যা আছে | মিল |
|---|---|---|---|
| আজকের বিক্রয় **500.00** | `/sales/invoices?from=…&to=…` | ১টা বিল · INV-0001 · **500.00** | ✓ |
| আজ আদায় **200.00** | `/sales/collections?from=…&to=…` | ১টা · COL-0001 · **200.00** | ✓ |
| আজকের ক্রয় **5,600.00** | `/purchase/bills?from=…&to=…` | ২টা · 1,600 + 4,000 = **5,600** | ✓ |
| হাতে নগদ **200.00** | `/accounts/cash-tills` | TIL-0001 প্রধান কাউন্টার · **200.00** | ✓ |

**একটাও বেমিল নেই।**

### ⓘ তবে দুই ধরনের কার্ড দুই রকম গভীরে নেয়

```
"আজ" টাইল          →  তারিখ-ছাঁকা তালিকা, ঠিক ওই লেনদেনগুলোই   ⭐ আদর্শ
"গোটা ব্যবসা" কার্ড   →  /dashboard/{module} — মডিউলের ড্যাশবোর্ড
```

যেমন "মজুদ বিক্রয়যোগ্য 165" চাপলে মজুদ-মডিউলের ড্যাশবোর্ড আসে, **ওই ১৬৫টার
তালিকা নয়**। মালিকের নিয়ম — "প্রতিটা সংখ্যা তার উৎসে নিয়ে যাবে" — কড়াভাবে
ধরলে মডিউল-কার্ডগুলো এক ধাপ কম যায়। মরা কার্ড নেই, তাই ব্লকার নয়; **তবে
নিয়মটা পুরো মানতে হলে ওগুলোকেও ছাঁকা তালিকায় নেওয়া উচিত।**
